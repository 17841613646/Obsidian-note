### 创建文件：touch 命令
语法：touch 「文件名」
如果文件不存在，则创建新文件
如果文件存在，则更新时间戳

批量创建语法 touch file1 file2 file3

![[Pasted image 20260913125909.png]]

### 复制文件与目录：cp命令

基础用法：文件复制
cp 【源文件】 【目标文件】
进阶用法：目录复制
cp -rp src_dir/ dest/
- -r：递归复制整个目录
- -p：保留权限、时间戳等元数据
复制目录是漏掉-r会报错

![[Pasted image 20260913130114.png]]

### 移动与重命名：mv命令

核心功能用法
- 移动：mv 【源文件】 【目标文件】
- 重置名：mv 【旧名字】 【新名字】
- 逻辑： 同一文件系统内仅修改目录项
- 效率：执行速度极快，无数据拷贝


![[Pasted image 20260913130715.png]]

### ！！！删除操作：rm命令及风险防范！！！

rm 【选项】 【路径】
- -r：递归删除目录
- -f：强制删除，忽略提示
- -i：交互模式，逐一确认

生产环境尽量使用-i选项逐一确定以防误删

![[Pasted image 20260913130831.png]]

### 高危操作警示：rm -rf

无提示递归删除，风险极高，除非已经反复核对过路径，一般杜绝使用rm -rf / 等误操作

删除之前可以使用mv把文件备份移动到/tmp

### 连接文件：软链接与硬链接

软链接类似于win快捷方式，源文件被删除后，连接失效
硬链接直接指向文件，硬链接被删除，只要还有链接就还能访问


| 对比项      | 硬链接 `ln 源 新`       | 软链接（符号链接）`ln -s 源 新`        |
| -------- | ------------------ | --------------------------- |
| 本质       | 给同一间仓库**再开一扇门**    | **另盖一间小仓库**，里面只放一张写着目标路径的纸条 |
| inode    | **和源文件同一个**        | **自己独立的、全新的 inode**         |
| 谁是"正主"   | **没有正主**，所有硬链接完全平等 | 有正主，源文件删了它就悬空               |
| 源文件被删    | 无影响（计数 -1，仓库还在）    | 变成**断链/悬空链接**，`ls` 显示红色     |
| 跨分区      | ❌ 不能               | ✅ 能                         |
| 指向目录     | ❌ 不能               | ✅ 能                         |
| 指向不存在的目标 | ❌ 不可能              | ✅ 可以（悬空链接）                  |
对照这张表，你说的每一步都对上了：

- **建文件** = 盖仓库 + 办房产证 + 门口钉一个门牌号
- **建硬链接**（`ln`）= 给这**同一间仓库再开一扇门**，再钉一个新门牌号。**没有新仓库、没有新房产证**，只是房产证上那个计数 **+1**
- **建软链接**（`ln -s`）= **另盖一间小仓库**（里面只放一张纸条，纸条上写着"真正的货在 XX 号门牌那间"）+ 给它办一张**完全独立的房产证**
- **`rm`** = 拆掉一个门牌号，房产证上计数 **-1**
- **计数归 0** → 房产证作废、仓库拆除，**空间才真正还回去**

所以你说的「inode 依旧没有被忘记」——说得特别准。**只要还有任何一个名字记得它，它就还在。**
