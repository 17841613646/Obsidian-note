### 一句话核心

**文件名是"门牌号"，inode 是"房产证"，数据块是"仓库里的货"。**
`rm` 只是拆门牌号；门牌号全拆光，仓库才塌。

---

### 一、四个角色，先认清谁是谁

| 现实世界 | Linux 里 | 说明 |
|---|---|---|
| 一间**仓库**（堆着真正的货） | **数据块** | 躺在硬盘上，真正占空间的东西 |
| 仓库的**房产证** | **inode** | 记录面积、建造日期、货放在哪几个货架……**唯独没有名字** |
| 钉在仓库门口的**门牌号** | **文件名**（目录项） | 人能看懂的"名字" |
| 房产证上写的「现有几个门牌号指向我」 | inode 里的**硬链接计数** | `ls -l` 的**第二列**就是这个数 |

> 查看 inode 号用 `ls -i`，配合 `ls -li` 能同时看到 inode 号和链接计数。

**inode 里存了什么**
- 文件大小、属主、属组、权限、时间戳（atime/mtime/ctime）
- **硬链接计数**
- 指向数据块的指针
- ❌ **不存文件名**——名字是挂在目录里的

---

### 二、硬链接 vs 软链接

| 对比项      | 硬链接 `ln 源 新`       | 软链接（符号链接）`ln -s 源 新`        |
| -------- | ------------------ | --------------------------- |
| 本质       | 给同一间仓库**再开一扇门**    | **另盖一间小仓库**，里面只放一张写着目标路径的纸条 |
| inode    | **和源文件同一个**        | **自己独立的、全新的 inode**         |
| 谁是"正主"   | **没有正主**，所有硬链接完全平等 | 有正主，源文件删了它就悬空               |
| 源文件被删    | 无影响（计数 -1，仓库还在）    | 变成**断链/悬空链接**，`ls` 显示红色     |
| 跨分区      | ❌ 不能               | ✅ 能                         |
| 指向目录     | ❌ 不能               | ✅ 能                         |
| 指向不存在的目标 | ❌ 不可能              | ✅ 可以（悬空链接）                  |

**为什么硬链接有那两个"不能"**
- **不能跨分区**：不同分区的 inode 号会撞车（都是各分区内部编号）
- **不能给目录做**：会绕成环，让系统遍历目录时"找不着北"

**软链接的一个小知识点**
它 inode 里存的就是那串**目标路径字符串**，所以 `ls -l` 看到软链接的"大小"= 路径长度（比如 `a.txt` 就是 5 字节）。

### 三、删除的真正机制

```
rm 某文件
   ↓
拆掉这个"门牌号"（目录项）
   ↓
inode 的硬链接计数 -1
   ↓
计数 > 0 ？ ── 是 ──→ 仓库原封不动，其他名字照样能访问
   │
   否
   ↓
还要看：有没有程序正打开着它？
   ├─ 有 → 空间暂时不还，等程序关闭再还
   └─ 无 → inode 作废 + 数据块回收，磁盘空间真正释放
```

**一句话**：**硬链接计数归 0，且无人打开，空间才真正释放。**

---

### 四、⚠️ 易错点：内存 ≠ 磁盘

| 东西 | 比喻 | 断电后 |
|---|---|---|
| **硬盘** | 家里的**书柜** | 东西还在 |
| **内存** | 桌上的**书桌** | 清空 |

文件内容是躺在**硬盘（书柜）**里的。
`rm` 释放的是**磁盘空间**，不是内存。
（`cat` 文件时会临时进内存，但那是「**看**」的动作，不是「**扔**」的动作。）

### 五、三个经典坑（运维面试爱问）

**1️⃣ 删了文件，磁盘还是满的**

现象：`rm` 掉一个大日志文件，`df -h` 一看空间没回来。
原因：**写日志的程序手里还攥着这个文件**（文件被打开着，计数归了 0 但空间不还）。
排查：`lsof | grep deleted` 找出是哪个进程。
解法：重启那个程序，空间立刻归还。

**2️⃣ inode 也会被用光**

现象：磁盘还有空间，却提示 `No space left on device`。
原因：**小文件太多**，把 inode 用光了（inode 本身也占存储）。
排查：`df -i` 看 inode 使用率。

**3️⃣ 目录的链接计数天然 ≥ 2**

因为每个目录里都有 `.`（指自己）和上一级目录里指向它的那个名字。
每建一个子目录，父目录的计数再 +1。

### 六、动手验证（照着敲，盯住 inode 号和链接计数）

```bash
echo "hello linux" > a.txt    # 盖仓库：inode 号 X，计数 1
ls -li a.txt

ln a.txt b.txt                # 硬链接：没有新仓库，a、b 的 inode 号相同，计数变 2
ls -li a.txt b.txt

ln -s a.txt c.txt             # 软链接：新仓库，c 的 inode 号不同
ls -li c.txt

rm a.txt                      # 拆掉 a 这个门牌号
cat b.txt                     # ✅ 照样能读！b 还记着那间仓库
cat c.txt                     # ✅ 也能读，因为仓库还在

rm b.txt                      # 最后一个门牌号也没了 → 此时才真正释放磁盘空间
cat c.txt                     # ❌ No such file or directory —— c 变成了悬空的纸条
ls -li
```

**预期结果核对表**

| 步骤 | inode 号 | 链接计数 | 能否访问 |
|---|---|---|---|
| 建 `a.txt` | X | 1 | ✅ |
| `ln a.txt b.txt` | a、b 都是 X | 2 | ✅ |
| `ln -s a.txt c.txt` | c 是 Y（≠X） | a/b 仍 2，c 为 1 | ✅ |
| `rm a.txt` | b 仍是 X | 1 | b ✅ / c ✅ |
| `rm b.txt` | X 消失 | 0 | c ❌（悬空） |

### 七、速查卡

```bash
ls -i  文件              # 看 inode 号
ls -l  文件              # 第二列 = 硬链接计数
ls -li 文件              # 两个一起看
stat   文件              # 最全：inode 号、链接数、三个时间戳

ln     源 新             # 建硬链接（同一 inode）
ln -s  源 新             # 建软链接（新 inode）

find / -inum <inode号>   # 靠 inode 号反查还有哪些名字指向它
lsof | grep deleted      # 揪出"删了但占着空间"的进程
df -h                    # 看磁盘空间
df -i                    # 看 inode 是否用光
```

### 八、自测题（合上笔记再答）

1. 我把 `a.txt` 建了 3 个硬链接，然后 `rm` 掉其中 2 个，第三个还能打开吗？为什么？能
   > 📝 **订正**：结论 ✅ 对，但「为什么」没答。`a.txt` + 3 个硬链接 = **4 个名字**，计数为 4；删掉 2 个后剩 **2**，**仍 > 0**，所以 inode 和数据块都还在，第三个自然打得开。口诀：**计数 > 0 就活着**。

2. 软链接自己的 inode 里存的是什么？存的是源文件路径地址
   > 📝 **订正**：✅ **完全正确**。延伸：正因存的是**写死的路径字符串**，源文件一改名/搬家软链接就断（这是设计如此，不是 bug）；硬链接无此问题，它认 inode 不认路径。

3. 为什么 `rm` 掉一个大日志文件后，磁盘空间可能没回来？1.还有这个文件还有链接，2.程序没有关闭
   > 📝 **订正**：✅ **两个条件都答到了**，这题答得最好。只提醒主次：答题时把「**程序没关闭**」放第一位——日志文件通常只有一个名字，`rm` 后计数已是 0，真凶基本都是**进程还攥着文件句柄**；「还有硬链接」理论上也成立，但实际少见。

4. 硬链接为什么不能跨分区、不能指向目录？ 因为不同分区的inode编号可能重复
   > 📝 **订正**：⚠️ 只答了一半。
   >
   > - **跨分区**这半句 ✅ 对：各分区 inode 独立编号，`5 号`在两边指的根本不是同一个东西，硬链接会跟丢。
   > - **漏了「不能指向目录」**：会**绕成环**——在目录里建硬链接指回自己的祖先，系统遍历目录树时会在圈里出不来；而且目录的 `..` 与父目录的链接计数是配套维护的，硬链接会破坏这套规则。

5. `ls -l` 里哪个数字是硬链接计数？为什么目录的这个数至少是 2？

-rw-r--r--. 2 xxp xxp 0  9月 13 03:27 a这里的2是连接数量
   > 📝 **订正**：⚠️ 第一问 ✅（就是权限串后面**第二列**）。**第二问漏答**：目录至少有**两个名字**指向它 —— ① 它自己里面的 **`.`**（指自己）；② **父目录里那个跟它同名的目录项**。每建一个**子目录**，父目录的数字还会再 **+1**（子目录里的 `..` 又多指它一次）。
   > 🔍 验证：`ls -ld /`、`ls -ld /etc`，看第二列的数字。

> **总评：3.5 / 5** —— 概念骨架是对的，扣分基本全在「只答了一半」。
