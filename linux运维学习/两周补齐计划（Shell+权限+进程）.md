## 0. 为什么做这个

2026.09.12 – 09.18 这 6 天，你完成了 Zabbix、JumpServer、Docker 三套企业级部署，**执行力完全没问题**。

但三件事本质是同一件事：**照着文档装软件**。这就是「部署员」。

|         | 部署员      | 运维工程师        |
| ------- | -------- | ------------ |
| 出问题     | 重新上网搜    | 知道从哪一层开始查    |
| 命令      | 复制粘贴能用就行 | 知道每个参数为什么这么写 |
| 100 台机器 | 装 100 遍  | 写个脚本跑一遍      |
| 面试      | 讲不清楚     | 能讲原理、讲排错思路   |

**最扎心的证据：** JumpServer 部署的核心是 `./jmsctl.sh install` —— 那是一段 Shell 脚本。
**你在使用自动化，但还不会制造自动化。**

### 两周后你要拿到的东西

> **一个 GitHub 仓库**，里面是对你已有项目的「自动化重做」：
>
> ```
> jumpserver-autodeploy/
> ├── init.sh                 # 系统初始化：网络、软件、防火墙、SELinux
> ├── deploy-jumpserver.sh    # 一键部署 JumpServer
> ├── health-check.sh         # 健康检查：8 个容器是否都在跑

> ```

**同一段经历，两种写法：**

| 现在的简历              | 两周后的简历                                                                     |
| ------------------ | -------------------------------------------------------------------------- |
| 照着文档部署了 JumpServer | **编写 Shell 脚本实现 JumpServer 的自动化部署、健康巡检与数据备份，将 8 个容器的部署流程从手工 40 分钟压缩为一条命令** |

**这就是「部署员」和「运维工程师」的距离。**

## 第 1 周：补三个洞

### 📅 Day 1–2｜用户与权限（面试出现频率最高）

**为什么现在补：** 你的笔记里**完全没有这块**。而这是面试第一个会问的技术点。

**要学：**
- 用户与组：`useradd` `usermod` `userdel` `groupadd` `passwd` `id` `su` `sudo`
- 三个核心文件：`/etc/passwd`（存什么？）、`/etc/shadow`（为什么要分开？）、`/etc/group`
- 权限：`chmod`（数字法 + 符号法）、`chown` `chgrp` `umask`
- 特殊权限：**SUID / SGID / 粘滞位**（你在 `lab` 里做过的题）

**🔗 和你已有项目的联系：**
> JumpServer 里的「RBAC 授权」「最小权限原则」「zhangsan 只能看被授权的资产」——
> **全都是 Linux 权限模型在企业软件里的翻版。** 你现在学的是它的地基。

**✅ 验收（达不到就重学）：**
1. 能解释 `-rwxr-xr--` 每一位的含义，以及对应数字
2. 给你一台陌生机器，15 分钟内：建用户 → 给 sudo 权限 → 建共享目录并做出「谁都能写、但删不掉别人的文件」
3. 能讲清为什么密码不存在 `/etc/passwd` 里

**🎤 面试怎么问：** "普通用户怎么临时获得 root 权限？`su` 和 `sudo` 有什么区别？"

---

### 📅 Day 3–4｜进程与服务管理

**为什么现在补：** 你已经在用 `systemctl stop firewalld`，但不知道它背后是什么。

**要学：**
- 进程查看：`ps aux`（每一列什么意思）、`top` / `htop`、`pgrep`、`pstree`
- 进程控制：`kill` `killall`、信号（`-9` 和 `-15` 的区别）、`nice` `renice`
- 前台后台：`&` `jobs` `fg` `bg` `nohup`
- 服务管理：`systemctl`（start/stop/restart/status/enable/disable）、理解 Unit 文件
- 日志：`journalctl`（`-u` / `-f` / `--since`）

**🔗 和你已有项目的联系：**
> 你装完 JumpServer 后执行的 `./jmsctl.sh start`，底层就是在**启动 8 个 Docker 容器进程**。
> 打开你的 JumpServer 服务器，敲 `ps aux | grep -c docker`，看看是不是 8 个。
> **这一刻，"部署"和"进程"就串起来了。**

**✅ 验收：**
1. 能找出当前机器上吃 CPU 最高的进程，说出它的 PID 和父进程，然后干掉它
2. 能讲清 `systemctl stop` 和 `systemctl disable` 的区别（**高频面试题**）
3. 能只看某个服务最近 10 分钟的错误日志

**🎤 面试怎么问：** "服务器负载很高，你怎么排查？"（提示：`uptime` → `top` → 定位进程 → 看日志）

---

### 📅 Day 5–7｜Shell 脚本基础（最重要的一周）

**为什么最急：** 你所有的项目最终都要靠脚本变成"可复用的能力"。

**要学：**
- 变量与引号（**单引号和双引号的区别是面试题**）
- 条件判断：`if` / `[ ]` / `test`
- 循环：`for` / `while`
- 函数
- 位置参数：`$1` `$#` `$@` `$0`
- 退出码：`$?` `exit` `&&` `||`
- 管道与重定向（你已经学过，这里要用起来）

**✅ 第一个脚本作业：系统巡检脚本**

写一个 `check.sh`，运行时输出：

```
========== 系统巡检报告 2026-09-20 15:30 ==========
主机名    : rocky-jumpserver
运行时间  : up 3 days, 4:22
系统负载  : 0.15, 0.08, 0.05
CPU 使用  : 12%
内存使用  : 1.8G / 3.9G (46%)
磁盘使用  : / 42%   /boot 18%
最占CPU的5个进程：
  PID   %CPU  COMMAND
 1234   8.2   java
 ...
================================================
```

**要求：**
- 全部用 Shell 变量和命令替换实现（不许直接 `cat` 一个写死的文件）
- 用函数封装，每个检查写成一个函数
- 有颜色输出（绿色正常 / 红色告警）

> 💡 **这个脚本可以直接写进简历。** 运维岗看到会心一笑——这是最经典的入门脚本。

## 第 2 周：把项目改成自动化

### 📅 Day 8–9｜脚本进阶

**要学：**
- `case` 分支
- 日志函数（写一个 `log_info` / `log_error`，输出带时间戳）
- 错误处理：`set -e` `set -u`、`trap`
- 参数处理：`getopts` 或简单的 `$1` 判断
- 定时任务 `crontab`（**五个星号分别代表什么，必背**）
- 文本三剑客在脚本里的用法：`awk` 取列、`sed` 替换、`grep` 过滤

**✅ 验收：** 你的 `check.sh` 加上 `--help`、日志记录、错误处理，达到"能给别人用"的水平。

---

### 📅 Day 10–12｜项目改造：JumpServer 自动化部署

**把你已经做过一遍的事情，写成脚本。**

| 脚本 | 内容 |
|---|---|
| `init.sh` | 配置静态 IP（`nmcli`）、安装基础软件、关防火墙、关 SELinux |
| `deploy-jumpserver.sh` | 解压安装包、执行安装、修改 `HTTP_PORT=8080`、启动服务 |
| `health-check.sh` | 检查 8 个 Docker 容器状态、检查 80/8080 端口、检查磁盘 |

**🔗 关键：这些命令你全都敲过了。** 这次只是把它们**写进脚本**，加上判断和错误处理。

**✅ 验收：** 从一台干净的 Rocky Linux 虚拟机开始，执行：

```bash
./init.sh && ./deploy-jumpserver.sh && ./health-check.sh
```

**全程不手工敲任何命令**，JumpServer 正常启动。

> ⚠️ 做不到就说明还没真会——**回去看是哪一步的命令你没理解。**

---

### 📅 Day 13–14｜收尾：写 README（这才是简历的核心）

**很多人做完项目就跑了。真正让你脱颖而出的是这份文档。**

`README.md` 要包含：

1. **项目简介** —— 一句话说清这是什么
2. **架构图** —— 画一张（可以用画图工具，或 Obsidian 的 Canvas）
3. **使用说明** —— 三条命令跑起来
4. **踩过的坑**（⭐ 最值钱的部分）：
   - 端口冲突：Zabbix 占了 80，JumpServer 改用 8080
   - SELinux 拦截：改 SSH 端口后 sshd 启动失败
   - `DOMAINS` 配置不能带端口号（v5 特性）
   - Ansible Docker 镜像缺失 → 关闭隔离
5. **后续优化方向** —— 显示你有思考（比如：用 Ansible 替代 Shell 脚本、加监控）

> 💡 **面试官打开你的 GitHub，第一眼看的就是 README。**
> 一份好的 README = 一个有深度的面试话题。
